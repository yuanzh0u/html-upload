# html-upload V2 需求文档（技能端）

- 版本：v1.0
- 日期：2026-10-22
- 归属：**技能端**（html-upload），消费服务端能力，不定义接口
- 依赖契约：`docs-api v2.0`，见 `html-platform/docs-service/docs/api/v2/contract.md`
- 冲突处理：本文件与契约冲突时**以契约为准**；技能不得自行扩展接口语义。
- 服务端需求见 `docs-service/docs/V2-requirements.md`；方案见 `docs-service/docs/V2-design.md`

---

## 1. 定位

html-upload 是 Agent 侧的上传与清单编排技能，**可服务多端**（Claude Code、OpenClaw、Cursor 等）。
V2 后它不再是唯一入口，而是“某个 Agent 完成一次上传/编排”的标准动作集。

边界：技能只负责本机侧的动作；平台能力、授权、存储全部在服务端。

## 2. 技能侧需求

### C-FR-01 契约版本协商 `[对应 FR-07]`

- 每次会话开始先 `GET /api/v2/me`，校验 `kind=api_key`、`api_version` 与 `capabilities`。
- 契约主版本不兼容时停止并明确告知，不做降级尝试。
- 验收：伪造不兼容 `api_version` 时技能拒绝继续，且不发起任何写请求。

### C-FR-02 上传 `[对应 FR-07]`

- 只接受本地 HTML 文件；上传前校验权限（`0600`）、大小、hash。
- `sha256` 必填；必须生成并复用 `Idempotency-Key`（同一请求重试复用，内容变更则新生成）。
- 上传参数只填契约允许字段，不发送 `owner_id`、`acl`、`visibility`、上传时间。
- 成功后本地留副本与 manifest 记录（不含 Key）。
- 验收：重复执行同一上传不产生第二条文档；改动标题后重传生成新请求；任何日志与输出不含 Key。

### C-FR-03 元信息拉取 `[对应 FR-08]`

- 支持分页拉取本人全部文档元数据，可输出为结构化清单（JSONL/表格）。
- 仅元数据，不得请求或存储正文。
- 验收：1000 条数据分页完整无重复无遗漏；输出可直接被 Agent 用于下一步编排。

### C-FR-04 清单编排 `[对应 FR-08]`

- 支持三种编排动作：改单篇元数据（标题/摘要/标签/分类）、全量替换编排（`PUT organization`）、单篇移动（`PATCH organization/documents/{id}`）。
- 写操作必须带 `If-Match`/`expected_version`；冲突时重新拉取后再决定，不盲目重试。
- 编排是“用户意图的落地”，技能不得自行编造分类或标签；不确定时向用户确认。
- 验收：批量编排 100 篇成功且版本一致；制造版本冲突时技能停下并要求刷新，不覆盖。

### C-FR-05 MCP 接入 `[对应 FR-08]`

- 技能需能以 MCP 客户端方式接入服务端 `/mcp`，并使用同一 Key。
- 不假设 MCP 连接可缓存授权；每次工具调用以当次验证为准。
- 验收：同一 Key 经 MCP 完成上传与编排，结果与 HTTP 路径一致。

### C-FR-06 Key 处理 `[对应 FR-06]`

- Key 只从本地受控文件或环境读取，不进入 argv、URL、日志、报告、manifest。
- 不打印前后缀或片段；引导用户到 `/console/keys` 获取与重置。
- Key 失效（401）时提示用户重新获取或重新生成，不自动重试。
- 验收：Key 出现在任何输出中即视为失败；401 时零自动重试。

### C-FR-07 错误处理 `[对应 FR-09 / 契约 §6]`

- 按契约错误码分类处理：400/422 提示修正输入；401 提示换 Key；403 提示权限不足；404 视为不存在或无权限，不推测；409 冲突按版本处理；429 遵守 `Retry-After`。
- 不向用户暴露 `request_id` 之外的服务端内部信息。
- 验收：构造各类错误时提示与契约一致，且无敏感信息回显。

## 3. 不做

- 不做网页端上传入口。
- 不做分享、好友、群组管理（服务端网页功能）。
- 不做正文读取或渲染。
- 不做 Key 生成（只在页面操作）。

## 4. 演进约束（多端复用）

- 技能行为不得依赖服务端部署位置、内网地址或特定模型。
- 平台地址、Key 通过配置注入；同一技能应能被不同 Agent 复用。
- 若未来出现第二个上传技能或第二个客户端，契约再抽为独立仓库；在此之前保持本文档薄、只引用契约。
