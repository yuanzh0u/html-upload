# 服务端错误与转述

错误体为 `{error, message, request_id}`；按工具 report 原样转述，保留请求编号，不输出凭据或服务端回显的敏感内容。以下建议与 client.ADVICE 一致；退出码取决于操作和结果是否确定，不能仅凭 HTTP 状态断言写入失败。

| 错误码 | HTTP | 含义 | 告诉用户 |
| --- | --- | --- | --- |
| `invalid_request` | 400 | 参数或请求字段不合法 | 请求格式不合法，请检查参数 |
| `summary_required` | 400 | 缺少必填摘要 | 请修正摘要 |
| `summary_too_long` | 400 | 摘要超出 1000 个 Unicode 字符 | 请修正摘要 |
| `unauthorized` | 401 | Key 无效、已重新生成或用户已删除，同形返回 | 登录后打开 https://docs.zh0uyuan.com/keys（「API Key」页面）生成或重新生成 Key，明文只显示一次；不要把 Key 贴进聊天，也不要写进带明文的命令或 shell history |
| `not_found` | 404 | 文档不存在、被删除或不属于用户 | 文档不存在或无权限 |
| `idempotency_conflict` | 409 | 同幂等键对应不同请求体 | 先确认是否为新内容，确认后才可加 --new |
| `file_too_large` | 413 | HTML 或请求体过大 | 请修正文件 |
| `not_utf8` | 415 | HTML 非法 UTF-8 | 请修正文件 |
| `daily_limit_reached` | 429 | 已达 UTC 当日上传/替换额度 | 已达日额度，请次日再试 |
| `internal_error` | 500 | 服务端内部错误，写入可能已生效 | 服务端内部错误，请稍后再试 |
| `storage_low` | 507 | 服务端可用存储不足 | 存储空间不足，请联系管理员 |

429 的 report 还带 Retry-After 秒数，不自动重试。500 等暂时错误和网络失败有有界重试；上传/替换重试保持原字节和幂等键。一次尝试结果未知后，即使后续收到 401、507 等明确错误，未过期时仍退出 4、记 remote_unknown 并保留原请求和恢复信息；后续可信成功响应可以确定成功。有效 pending 补发也保留先前的不确定性，账户、上传补发前清单或当前元数据前置查询失败不能当作此前写入失败。未过期的补发清单分页异常或不完整也退出 4、保留档案和恢复命令，不继续发送；清单完整且找到标题、HTML 字节数相同的文档时按成功清档，不再发送。未过期的未知结果退出 4 时用 resume，并按需要先 list/get 核对；edit、favorite、unfavorite、delete 结果未知时用 get 核对。不要为清除错误擅自另建文档。

远端已确认成功（含补发清单命中）而本地记录失败时，退出 4 的 data 仍保留 id、url、title 和恢复命令，report 说明「文档已经上传成功：<url>；本地记录没写进去，用 resume 补记」。meta 中已原子保存 success 时，resume 核对站点、Key 与私有元数据后只离线补记并清档，不进行任何网络请求；不得把本地记录失败转述为上传失败或建议另传一篇。

连接超时为 10 秒；正文按 64 KiB 原始字节块发送，每块使用 30 秒 socket 超时，响应读取仍使用 30 秒 socket 超时。慢速上行的整个正文发送可以超过 30 秒。请求显式携带完整 Content-Length，不使用 HTTP chunked 编码；重试从第一字节开始，保持完整请求体和幂等键不变。

未定结果的档案从 prepared_at 起满 24 小时即记 abandoned 并清理，退出 4 且不再给 resume_command。upload resume 在作废前仍完成只读清单查找，命中按成功处理；未命中、查询失败或不完整都作废。已过期 replace 不再查版本或补发；查询、传输或重试等待期间到期也禁止后续发送。报告为「超过 24 小时，服务端已不记得这次请求，不会重发；请用 list 核对，确认没有成功的话，重新执行 upload/replace」。这不表示远端失败；已知可信成功仍按成功补记。普通命令开始会离线清理其他安全有效的过期档案；本地作废或清理失败会提示核对，可能保留文件，但不会建议无效的 resume。
